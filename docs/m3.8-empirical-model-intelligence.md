## Architecture

### EmpiricalHistory (SQLite)
```
~/.harness/empirical.db
├── executions (record_id, model_id, task_type, outcome, duration, tokens, ...)
├── idx_emp_model
├── idx_emp_task_type
├── idx_emp_timestamp
├── idx_emp_outcome
└── idx_emp_model_task
```

### ModelPerformanceAggregator
- Time-decay weighting (30-day half-life)
- Recent window tracking (last 20 tasks)
- Per-task-type segmentation
- Sample confidence calculation

### TaskAwareRouter
- Static capability fit via TaskRequirementProfile
- Empirical task success weighted by confidence
- Legacy history bonus from PerformanceHistory
- RoutingExplanation with full provenance

### Confidence System
| Samples | Confidence | Routing Weight |
|---------|------------|----------------|
| 0 | UNKNOWN | 0.0 |
| 1–4 | VERY_LOW | 0.1 |
| 5–19 | LOW | 0.3 |
| 20–49 | MEDIUM | 0.6 |
| 50+ | HIGH | 1.0 |

## Validated Behaviors

1. **Empirical data influences ranking** — Models with good history rank higher ✅
2. **Static capabilities used for cold start** — New models route on metadata ✅
3. **Routing explanation shows provenance** — Users see why a model was selected ✅
4. **Task-specific performance** — Different tasks use different empirical segments ✅
5. **Time decay** — Recent performance outweighs old performance ✅
6. **Recent window** — Last N tasks tracked independently ✅
7. **Multiple task types** — Correct model selected per task type ✅

## Known Limitations

1. **Empirical data requires real runs** — No data until agent executes tasks
2. **Free tier rate limiting** — Free models may hit 429
3. **Session resume not implemented** — Storage exists, resume logic planned for M4
4. **No exploration** — Always exploits current best (exploration_rate planned)
5. **No Rust/C++** — All Python until profiling proves bottleneck
