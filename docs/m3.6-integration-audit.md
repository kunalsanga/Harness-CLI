### Critical Integration Gaps

#### GAP 1: ModelRegistry ↔ ModelRouter (SEVERE)
- ModelRouter discovers models from providers directly
- ModelRegistry exists but is not consumed by the router
- Registry has capability profiles; Router uses raw ModelInfo
- **Impact:** Task-aware routing ignores empirical capability data

#### GAP 2: TaskClassifier ↔ AgentLoop (SEVERE)
- TaskClassifier classifies tasks
- AgentLoop does NOT classify tasks
- Routing mode is a static config, not task-driven
- **Impact:** Every task uses the same routing strategy

#### GAP 3: ContextEngine ↔ Advanced Components (MODERATE)
- ContextEngine has basic project discovery
- NOT integrated with RepositoryAnalyzer, RelevanceRanker, SymbolIndex, DependencyGraph, ContextPackBuilder
- **Impact:** Context is basic file listing, not intelligent

#### GAP 4: PerformanceHistory ↔ Routing (MODERATE)
- PerformanceHistory records data
- Routing decisions don't use historical performance
- **Impact:** Models aren't selected based on track record

#### GAP 5: Benchmark Engine Not Executing (MODERATE)
- AgentBenchmarkEngine exists but `_execute_tool` is simulated
- No real provider calls during benchmarks
- **Impact:** No actual model capability measurement

#### GAP 6: No Run/Session Tracking (MODERATE)
- AgentLoop completes tasks but doesn't persist results
- No run history visible through CLI
- **Impact:** Can't see what happened after a run

#### GAP 7: No Task Classification in Routing Pipeline (MODERATE)
- Router._build_scoring_context uses keyword heuristics
- TaskClassifier is more sophisticated but unused by router
- **Impact:** Suboptimal task-tag detection

### Dead/Duplicated Code

1. `ContextEngine._file_cache` — duplicates FileContentCache functionality
2. `Router._build_scoring_context` duplicates task classification logic from TaskClassifier
3. `models/history.py` (PerformanceHistory) and `routing/health.py` (HealthTracker) track overlapping data
4. Benchmark tasks in `benchmarks/tasks/` are defined but never executed by the engine
